# Excel取り込み：比較前値置換ルール（ハッチ機能）設計メモ

（作成: 2026-10-02）

## 【重要】権限管理実装時の対応事項

この機能、および既存の「除外リスト」（`docs/AMFPHP連携_差分除外リスト.md`）は、いずれも**本来はDBまたは管理簿（Excel）側を是正すべき差分を、見た目上検出させない・比較から除外する**という性質を持つ「安全弁の消極的な使い方」である。

このツールの核となる目的（Excel取り込みの差分レビューによるヒューマンエラー防止）と、この2機能は本質的に緊張関係にある。**客先が自分でこれらの管理画面を使えてしまうと、「差分を直す」のではなく「差分を見えなくする」方向にインセンティブが働き、ツールの存在意義を損なう。**

そのため、この2機能（除外リストの管理・比較前値置換ルールの管理）は、**社内（運用PC側）の内部利用・客先納品前のDB整備作業専用**と位置づける。`docs/デプロイ構成.md`に記載の「有効にする機能を権限（ロール）で出し分けて両拠点に配置する」という既存方針に沿い、**将来、権限管理機能（権限管理／ユーザー権限管理画面）を実装する際、この2つの管理UIは客先ロールには一切見せない**こと。

2026-10-02時点では権限管理機能自体が未実装のため、コード上のロール分岐はまだ入れていない。権限管理機能に着手する際は、本メモと`docs/AMFPHP連携_差分除外リスト.md`を必ず参照し、対応漏れが無いようにすること。

## 背景・目的

管理簿とDBの間に、表記ゆれ等により毎回必ず出てしまう既知の差異がある場合（例：会社名の旧表記・新表記など）、行単位で除外リストに載せる「除外リスト」機能とは別に、**特定の列の特定の値だけを、比較前に別の値とみなして正規化する**機能が欲しい、という要望。

- 除外リストとの違い：除外リストは「この行は差分として出てもデフォルトで適用しない」（行単位）。本機能は「この列のこの値は、そもそも差分として検出しない」（値単位・全行共通）。
- 適用範囲：特定のアカウントNoに限らず、どの行であっても同じルール（列＋Excel側の値＋DB側とみなす値の組）が効く。

## 設計：比較前に正規化する（差分検出後に隠すのではない）

当初案「差分としては検出するが表示だけ隠す」は採用しない。理由：`computeImportDiff`が組み立てる`after`（実際にDBへ書き込む内容）には、他の列が本当に変更された場合、**正規化されなかった生のExcel値がそのまま載ってしまう**。差分検出だけを抑制しても、同じ行の別列が変更されてapplyされた瞬間、意図せずDBの値を上書きしてしまう危険がある。

そのため、**Excelパース直後・差分計算（`computeImportDiff`）の前**に、ルールに一致する値を正規化してしまう設計にする。

```
パース結果（Excel生データ）
  → 値置換ルール適用（field一致＆値一致なら置き換え）
  → この正規化後の値で、比較・差分表示・実際の書き込みすべてを行う
```

`preview`・`apply`の両エンドポイントで同じ正規化処理を通すことで、画面に表示される内容と実際に書き込まれる内容が常に一致する。

## 対象列の制限

列名の誤字や存在しない列を登録しても静かに無効なルールになってしまうため、**文字列型の列のみ**をホワイトリスト化して許可する（`accountAuthDiff.ts`の`NORMALIZABLE_FIELDS`）。`number`（数値）・`non_sync`/`delfg`（真偽値）は対象外とする：これらは型変換を要し、今回のユースケース（表記ゆれの吸収）にも合わないため、スコープを絞った（YAGNI）。将来必要になれば型ごとの変換処理を追加する。

登録（追加API）時に、`NORMALIZABLE_FIELDS`に含まれない列名はエラーで弾く。

## 保存先・データ構造

除外リストと同じ`_properties`テーブル（`DbManagerProperties`経由）に、別の`category_key`で持たせる。

- `category_key`: `'account_auth_import_value_normalize'`
- `value1_1`: 対象列名（`AccountAuthInput`のキー文字列。例：`'company_name'`）
- `value1_2`: Excel側の値（例：`'A商事'`）
- `value1_3`: DB側とみなす値（例：`'A商事（新）'`）
- `del_fg`: 論理削除（除外リストと同じ考え方）

## API

除外リストと同じCRUD形（`account-auth/import/normalize-rules`）。

```
GET    /account-auth/import/normalize-rules
POST   /account-auth/import/normalize-rules   body: { field, fromValue, toValue }
  → fieldがNORMALIZABLE_FIELDSに無ければ400
DELETE /account-auth/import/normalize-rules/{id}
```

## 画面

除外リストの管理ダイアログと同じ構成（一覧・追加・削除）で、`ImportDiffDialog`のツールバーから開ける別ダイアログを新設する。差分プレビューのグリッド自体には、正規化を明示する特別な表示は今回は作らない（YAGNI。必要になれば追加）。
